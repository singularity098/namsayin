### Xythos
- Named Xythos (owner, 2026-10-29; was NAMsayin), and hosts list its developer as Xythos too (was the owner's username). Its logo is the owner's pick from 36 concepts: a glowing violet crop circle (six satellites growing in size, like six strings) left of the wordmark, thin geometric letters (the moon on the O was removed at the owner's request, 2026-10-29). It's shown big in the top bar
- An LV2/VST3 plugin (and AU on macOS) written in C++ using DPF and NeuralAmpModelerCore (no standalone application for now)
- The plugin is ultra-light, fast, and snappy
- Zero latency by default: latency (plugin delay compensation, PDC) is only introduced by blocks that require it, and is reported to the host
- Natively runs on Linux and Windows, x86-64 only, and requires a CPU with AVX2/FMA. macOS too (owner, 2026-10-24): macOS 11 or later, a universal binary for Apple Silicon and Intel (Intel Macs need AVX2/FMA, 2013 or newer), in VST3, LV2 and AU. Signed ad hoc until there's an Apple Developer ID, so macOS needs the quarantine flag cleared after downloading. Status: built, checked by CI; needs testing on a Mac
- Beautiful interface with a very dark theme, drawn with NanoVG: the window shows the owner's dark background image where there are no controls (owner, 2026-10-28; was plain black from 2026-10-26, before that the owner's dark wood image), everything in the window is translucent black at 50% with an ultra-thin gray outline (no gradient): the top bar, the chain's blocks, the block panel, the bottom controls, the tuner and metronome; everything that appears over them (all dialogs, menus, help popups and the toast) is black at 95%, so it reads clearly, and the blocks and files listed in Add Block 97% (owner, 2026-10-29; was 90% everywhere, then 93% over a blur for the popups, which was dropped). The background image must show no compression artifacts: it's embedded exactly as the owner gave it, and re-encoded only losslessly. Each block in the chain has a white power button in its upper left corner that turns it on and off (owner, 2026-10-28; was a green dot). While a block is bypassed, the controls in its panel turn dark gray: they still work, but show they don't affect the sound. Font: Jost Light. Knobs: a black body with a hairline edge, a scale of ticks lit up to the value, and a dot marking the position (owner's choice from drafted options, 2026-10-22)
    - The highlight colour is configurable in Settings; white by default (owner, 2026-10-26; was blue, before that purple)
    - Outlines, buttons, fills and knobs (owner, 2026-10-29): Solid (the highlight colour), or Smooth or Splotchy: 2 or 3 colours painted across the whole window. Five presets (Iris, Sunset, Ocean, Mint, Gold), or any colour from the picker. Colours must be light: below a relative luminance of 0.12 (about 3:1 on the dark window) they're lifted toward white. No animation. Text is not painted with the gradient: NanoVG draws glyphs with the paint's colour alone, so text keeps its plain colour (the owner's request for gradient text was not possible this way; see Architecture).
    - Default (owner, 2026-10-30): Splotchy in #7278fe, #c688d6 and #a85eea (the Iris preset, listed first). The other presets and the Solid accent swatches are pale, which works better on the black window.
    - Colour picker (owner, 2026-10-30): a colour wheel with a brightness slider, the colour's name as it moves ("pale indigo"), its hex value as selectable text that can be copied (and typed), and colours saved as presets of the user's own (click to use, × to forget). It sets the accent (Solid) or each gradient colour.
    - The logo's crop circle takes the highlight colour, the gradient's where it sits when one is on (owner, 2026-10-30; was fixed violet).
    - Pedals have a power LED: lit while the block is on, dark while it's bypassed (owner, 2026-10-26); on image faces it is a photographed LED (Krea-2) tinted to the pedal's colour (owner, 2026-10-26)
- The interface can be resized and scales for high DPI displays
- Free, open source software under the MIT license
- Supports NAM A1 and A2
  - A2 is the 2026 NAM architecture; one A2 file can run in Full or Lite (lower CPU) mode
- Supports an IR cab loader
- Settings panel where the user can:
    - Specify the directory for NAM files and separately for IR files, with refresh/rescan button
    - Select NAM A2 size, lite or full (global default)
    - Add per-block NAM A2 size, if desired (overrides the global default)
    - Turn on per-block volume normalization, using the loudness metadata in NAM files; IRs can also be normalized
    - Multi-core processing: the two parallel branches of a split run on separate cores
- Settings and favorites are stored in one global config file per user, shared by all plugin instances
- The scanner for NAM and IR files is able to see inside of zip files and load those files as if they were already extracted
- NAM models show what they capture, from the file's gear type (Amp + Cab, Amp Head, Cabinet, Pedal, Outboard, Spaces, Experimental), and their architecture (A1 with its size, A2, LSTM, ...), in Add Block, on the block's tile and in its panel (owner, 2026-10-30). A warning shows when an Amp + Cab model has an IR (or a cabinet model) after it, or an Amp Head model has none after it
- Allows user to star/favorite NAM files in the interface. Favorites are tied to the file's content hash, so they survive the file being moved or renamed
- Has a built-in very high performance and high accuracy tuner, with traditional or strobe modes. The tuner can be toggled on with a button in the top-right of the window.  The guitar sound is by default muted when the tuner is engaged, but the mute also can be toggled on or off
    - The tuner reads the dry input (before the signal chain), with a gain boost so that quiet inputs are not a problem
    - Adjustable reference pitch (A4 = 415–466 Hz, default 440)
    - Drawn in the knobs' style: a hairline tick scale lit from the centre to the pitch with a dot for the needle; the strobe's bands are tick lines (owner's request, 2026-10-23)
    - Accuracy target: ±0.1 cent, from a 5-string bass's low B (31 Hz) up to the 24th fret of a guitar's high E string
- Also has a built-in metronome which can be toggled on and off from a button next to the tuner. It has the same features as the metronome in Fretbored (https://github.com/singularity098/fretbored):
    - Tempo 20–300 BPM, tap tempo
    - Meter: 1–16 beats over 2, 4, 8 or 16; beat grouping for compound/odd meters (e.g. 7/8 as 2+2+3)
    - Per-beat accents: accent / normal / soft / mute
    - Subdivisions: eighths, triplets, sixteenths, quintuplets, sextuplets, swing, dotted, and mixed 8th/16th figures
    - Sounds: Classic, Digital and Beep; separate volume for subdivisions. All generated in code, no samples (owner, 2026-10-23: so they are our own; Classic recreates the click the owner supplied)
    - Trainer: Step mode (+N BPM every M bars from start to end tempo) and Gradual mode (smooth ramp over N bars); works for slowing down too
    - Gap trainer: play N bars, then mute M bars
    - Visual pulse synced to what you hear (the swinging pendulum ball was removed: at host redraw rates it looked choppy; owner's request, 2026-10-23)
    - Sample-accurate timing
    - Tempo is independent of the DAW by default; a switch syncs tempo and transport to the DAW instead
    - Keyboard shortcuts only apply while the plugin window has focus
- Has a linear signal chain which runs from left to right, where users can add NAM, IR, or built-in effects, up to a maximum of 32 blocks
- Near the metronome and tuner is another button which links to my other free application Fretbored: https://singularity098.github.io/fretbored/
- The buttons at the top right of the window (Fretbored, metronome, tuner, settings, bypass) are icons that show what they do; the Fretbored button uses the Fretbored app icon (owner's request, 2026-10-22; redrawn from its updated icon, 2026-10-29: the fretboard grid with the notes spelling an F)
- A GitHub button (the GitHub mark, in the icons' hairline style) next to the Fretbored button opens the project's GitHub page, https://github.com/singularity098/xythos (owner's request, 2026-10-23)
- Every knob and control has a highly detailed but easy to understand plain-English explanation of what it does and how to use it, shown in a translucent popup when the mouse hovers over it (owner's request, 2026-10-22)
- The signal chain may be split into 2 at any point, and then merged back into 1 at any other point, allowing for effects to run in parallel, or multiple NAM simultaneously
    - Only one split at a time
    - A small split icon appears on the signal line between blocks while the mouse is over the gap; clicking it adds an empty split there (owner's request, 2026-10-22)
    - The merge has controls for A/B balance, level, pan and phase invert per branch, and Align: delays one branch by up to 5 ms to line up two amps (owner, 2026-10-29). Invert A is off by default (owner, 2026-10-29: was on for a while, but the owner's captures being out of phase was bad luck, not common)
    - Pan works in Mono mode too: the chain is stereo after the merge (owner, 2026-10-29), and from the Delay on (its stereo modes)
    - The two branches are time-aligned at the merge if their latencies differ
- The blocks in the signal chain are square shaped, and we will use provided images (later possibly as small thumbnails on the tiles)
- The panel below the chain shows the selected block: a large, high-quality image of the pedal/amp/cab on the left of the panel, and the block's generic knobs centred next to it, spread out to fill the space (owner, 2026-10-28; were right-justified). Until real images exist, a drawn placeholder (pedal, amp head or cab) is shown, in the "Neon" style (black enclosure outlined in glowing lines of the category colour, with a symbol on its face that is unique to each pedal and drawn from its name and purpose (owner's request, 2026-10-23; the Doubler's photo was removed so every block has the same neon look); owner's pick from six mockups; the second style, "Panel", was removed at the owner's request, 2026-10-23). NAM models and cab IRs without an image of the user's each get a look of their own, picked from the file's path (owner's request, 2026-10-24; the path rather than the content hash, owner's call for consistency): amps are always a wide head (owner, 2026-10-25: like a traditional amp head, no combos) in reds and oranges, mostly red (owner, 2026-10-25), and vary in knob count, grille pattern, logo and their shade of red or orange; cabs (always 2x2, owner's call) in cone, grille cloth, logo, corner protectors and colour. A file looks the same everywhere it appears (chain, library, presets); moving or renaming it changes its look. Later the generic knobs may be removed so knobs are turned on the image itself (needs images prepared by the owner first). Proof of concept (owner, 2026-10-25): the Poly Chip has the owner's pedal image with two knobs on its face (Crush and Mix), drawn from the owner's knob image and its lighting layer; they turn the same parameters as the panel's knobs, so turning either turns both; other blocks keep the neon look
    - Pedal photos (owner, 2026-10-28): every pedal has the owner's photo (Krea-2 renders, one picked from four per pedal), cropped to the pedal, with 2-3 knobs on its face for its most important controls (one on the Volume pedal, two on the Whammy and Wah, whose treadles leave room only at the heel), turning the same parameters as the panel's knobs. The knobs are the owner's blue-rim knob, the rim tinted to the colour of the pedal's glyph; the treadles have plain black knobs. Each has a power LED north of its footswitch (on the photo's indicator spot), lit while the block is on; clicking the latching footswitch (a treadle's toe) turns the block on or off. Face knob names are shortened to at most five letters ("Damping" is "Damp") in small type, and three knobs sit in a shallow triangle, the middle one higher, so the names don't run into each other; the knobs' reflections stay put while they turn, only the pointer moves (owner, 2026-10-28). The images are embedded in the plugin as high-quality WebPs at twice the earlier resolution (1280 px high; owner 2026-10-28 after seeing compression artifacts in the JPEGs, about 115 KB each) and decoded only when shown; tiles and lists use small thumbnails, and only the last few full-size images stay in memory. New pedals get an image prompt for Krea-2 (`docs/PedalImagePrompts.md`), with a glyph unique to the pedal
- Speaker cabinet images (owner, 2026-10-29): IR blocks show one of the owner's cab photos, sorted by size into Bass (1x10", 2x10", 4x10") and Guitar (1x12", 2x12", 4x12"). Each IR gets a 4x12" somewhat at random from its file's content hash (owner, 2026-10-29: most IRs are of a 4x12; was any size), or one of the size its file name gives, like "2x10", when it gives one. Right-clicking an IR in Add Block, or the cab image in an IR block's panel, opens the cab image dialog: six sections, one per size, that open to show their cabs. These replace the drawn 2x2 cab looks
- User images (owner, 2026-10-29; replaced sidecar images, an image file next to a NAM file or IR with the same name): users can add their own images for amps, cabs and pedals. They're copied into the config directory, where there are separate libraries of user images for amps (NAM blocks), cabs (IR blocks) and pedals (every other block). The block panel's Image… button shows the block's library and its stock image: pick one, add an image file, or delete one (it asks again). A custom image is just the static image: no power LED, knobs or footswitch on it. If a custom image is deleted, the blocks that used it fall back to their stock image. Exported presets carry the images they use, and opening one adds them to the user's libraries

### Version 1 scope
